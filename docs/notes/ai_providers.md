# Notes: ai_providers

Detailed notes moved out of `CLAUDE.md` (the hard rules stay there). Read this before editing `ai_providers.py`.

- `ai_providers.py` — vendor-neutral AI layer plus API-key management, **per user**: every public function takes `user_id` first (`list_keys`, `manage_keys`, `resolve`, `ask`, `info`) and keys live in `user_ai_config` as `{active_key_id, keys: [{id, name, provider, value, model, expires, notes, created}]}` — deliberately **not** in the user's data blob, so keys never reach exports/backups. **Never return a key's `value` to the page** (`_public_key()` exposes only the last 4 chars); on `update` an empty value means "keep". Keys are encrypted at rest by `auth.write_ai_config()`/`read_ai_config()` (callers here always see plaintext). `ask()` uses only the active key, refuses it if `expires` is in the past, and falls back to the provider's `default_model` (only Anthropic has one) when `model` is empty. No env-var fallback. Vendors: `anthropic`, `openai`, `gemini` (own SDKs) and `mistral`, `deepseek`, `xai`, `openrouter` (`OpenAICompatibleProvider`: the `openai` SDK with the vendor's `base_url` and chat completions — adding another OpenAI-compatible vendor is a 5-line subclass). Only Anthropic has a `default_model`; never guess model names for the others. `AnthropicProvider.request_options()` sends adaptive thinking / `effort` / server-side `fallbacks` only to models listed (by ID prefix) in `ADAPTIVE_THINKING_MODELS` / `EFFORT_MODELS` / `FALLBACK_MODELS` — e.g. `claude-haiku-4-5` gets a plain request; extend these tables when adding models. If a 400 still says an option is "not supported", it retries once without them. Show vendors' error text via `api_error_message()`, not the raw exception dump. Each provider lazy-imports its SDK. Some vendors report a bad key as 400 (Gemini `API_KEY_INVALID`, xAI "Incorrect API key"): map those to the "chiave non valida" message. Adapters must translate every vendor error into `AdvisorError(message_in_italian, http_status)`. To add a vendor: subclass `Provider`, implement `import_sdk`/`make_client`/`ask`, register it in `PROVIDERS`, and add its key prefix to `detectApiKeyProvider()` in the page.
