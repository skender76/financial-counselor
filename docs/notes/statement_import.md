# Notes: statement_import

Detailed notes moved out of `CLAUDE.md` (the hard rules stay there). Read this before editing `statement_import.py` / the statement-import section of financial-dashboard.html.

- `statement_import.py` — reads bank statements for the "📑 Importa estratto conto" item of the Impostazioni menu (`POST /api/import-statement` `{account, kind, filename, content_b64, since?}` → `{movements, ignored, summary}`; the file travels base64-encoded inside JSON to satisfy the JSON-only POST rule). `parse_statement()` dispatches by account: Revolut `.csv`, BPER `.xls` (needs `xlrd`), Fineco `.xlsx` (needs `openpyxl`, lazy-imported); `kind` `carta` (credit-card report) exists only for BPER. It only normalizes — each movement is `{date, direction, account, movement, amount>0, description, details, tag, provisional, source_kind}` with `movement` using the Movimenti register's values and `tag` a hint (`stipendio`, `mutuo`, `possibile_giroconto`, `spese_bancarie`, `imposte`, `investimento`). Only movements from `IMPORT_START_DATE` (2026-01-01) are returned; Revolut currency exchanges (`cambio_valuta`) and BPER account card settlements (`regolamento_carta`) are not expenses and go to `ignored` instead (the settlement lines of the card report are dropped, otherwise card spending is counted twice). BPER files are cross-checked against their own row count and Totale row. No bank file carries a stable transaction ID, so matching relies on account+direction+amount+date.

The page side (`// ===== Importazione estratti conto` in `financial-dashboard.html`) does the rest, nothing is written until the review screen is confirmed: the file is the source of truth for its window — a registered movement with the same account/direction/amount and date ±3 days is **replaced** (keeps its `id`, its manual category unless it is `Varie`/`Altro`/`Altro reddito`, and `autoMortgage`, otherwise `applyRecurringMortgage()` would regenerate the instalment), unmatched file rows are added, registered movements missing from the file are **flagged** (default "Mantieni", never auto-deleted). Imported entries carry `imported`, `source`, `noBalance: true` (account balances never change on import, so `deleteExpense`/`deleteTransfer` skip the balance reversal for them) and, for card purchases, `ccApplied: true`. Own-account transfers are paired across accounts (equal amount, opposite direction, ±3 days, at least one leg a `possibile_giroconto`/`transferHint`) and become an entry in `skender_fin_transfers_v1` replacing both legs; a leg already covered by a registered transfer is not imported. Categories: deterministic by tag → learned rules (`skender_fin_category_rules_v1`, learned only from categories the user set or already had, never from unreviewed AI output) → AI via `askAdvisor` (batches of 40, descriptions masked by `maskForAi`: IBANs, long numbers and names after "a favore di"/"Beneficiario" removed; no dates or account names are sent). `Varie` is never suggested because it requires a `necessity`.
