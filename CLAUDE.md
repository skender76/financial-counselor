# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Personal finance dashboard ("Dashboard Finanziaria") for a single user. UI text, code comments and log messages are all in **Italian**; keep new ones in Italian too. There is no build step, no package manager and no test suite. Git-tracked; `dati.json` (real financial data) and `ai-config.json` (API keys) are gitignored and must never be committed.

## Files

- `financial-dashboard.html` — the whole dashboard (HTML + CSS + JS in one file), served by `server.py`. The AI chat goes through `askAdvisor()`, which POSTs to `server.py`'s `/api/ask`; `loadAdvisorInfo()` reads `/api/ai-info` at startup to show the active vendor/model under the chat; opening the HTML file directly (not via `localhost:8765`) leaves the chat and file sync without a backend. The `#fileSyncStatus` header indicator shows whether writes are reaching `dati.json`.
- `server.py` — Python 3 server on `localhost:8765`: serves the dashboard at `/` and exposes `GET/POST /api/data` backed by `dati.json` (atomic write via `.tmp` + `os.replace`), and delegates the AI endpoints (`POST /api/ask` `{prompt}` → `{text}`, `GET /api/ai-info`) to `ai_providers.py`. Otherwise stdlib only. Everything is sent with `Cache-Control: no-store` on purpose (stale caching caused problems before). Request hardening (`_reject_foreign_request`): every request must carry `Host: localhost:8765` or `127.0.0.1:8765` (blocks DNS rebinding), and every POST must be `Content-Type: application/json` (a cross-site page can't send that without a CORS preflight, which the server doesn't answer) — keep both when adding endpoints, and send JSON from the page. Graceful stop: `POST /api/shutdown` (used by the header's "⏻ Chiudi dashboard" button, which first awaits a final `syncToServerFile()`), Ctrl+C, SIGTERM or SIGHUP (Terminal window closed) all end `serve_forever()`, then wait on `DATA_LOCK` so an in-progress `dati.json` write finishes. `server.shutdown()` must run off the serving thread (`request_shutdown()`). If port 8765 is already taken, `main()` opens the running instance instead of crashing. The page is re-read from disk on every request but `server.py`/`ai_providers.py` only at startup, so after changing Python code the running server must be restarted; the page shows an "outdated server" message when `/api/ai-keys` returns 404.
- `ai_providers.py` — vendor-neutral AI layer plus API-key management. Keys are managed from the page's "🔑 Chiavi API" section via `GET/POST /api/ai-keys` (`manage_keys()`: `add`/`update`/`delete`/`activate`) and stored in `ai-config.json` as `{active_key_id, keys: [{id, name, provider, value, model, expires, notes, created}]}` — deliberately **not** in `dati.json`, so keys never reach exports/backups; written atomically with mode 600 under `CONFIG_LOCK`. **Never return a key's `value` to the page** (`_public_key()` exposes only the last 4 chars); on `update` an empty value means "keep". `ask(prompt)` uses only the active key, refuses it if `expires` is in the past, and falls back to the provider's `default_model` (only Anthropic has one) when `model` is empty. No env-var fallback. Vendors: `anthropic`, `openai`, `gemini` (own SDKs) and `mistral`, `deepseek`, `xai`, `openrouter` (`OpenAICompatibleProvider`: the `openai` SDK with the vendor's `base_url` and chat completions — adding another OpenAI-compatible vendor is a 5-line subclass). Only Anthropic has a `default_model`; never guess model names for the others. `AnthropicProvider.request_options()` sends adaptive thinking / `effort` / server-side `fallbacks` only to models listed (by ID prefix) in `ADAPTIVE_THINKING_MODELS` / `EFFORT_MODELS` / `FALLBACK_MODELS` — e.g. `claude-haiku-4-5` gets a plain request; extend these tables when adding models. If a 400 still says an option is "not supported", it retries once without them. Show vendors' error text via `api_error_message()`, not the raw exception dump. Each provider lazy-imports its SDK. Some vendors report a bad key as 400 (Gemini `API_KEY_INVALID`, xAI "Incorrect API key"): map those to the "chiave non valida" message. Adapters must translate every vendor error into `AdvisorError(message_in_italian, http_status)`. To add a vendor: subclass `Provider`, implement `import_sdk`/`make_client`/`ask`, register it in `PROVIDERS`, and add its key prefix to `detectApiKeyProvider()` in the page.
- `statement_import.py` — reads bank statements for the header's "📑 Importa estratto conto" button (`POST /api/import-statement` `{account, kind, filename, content_b64, since?}` → `{movements, ignored, summary}`; the file travels base64-encoded inside JSON to satisfy the JSON-only POST rule). `parse_statement()` dispatches by account: Revolut `.csv`, BPER `.xls` (needs `xlrd`), Fineco `.xlsx` (needs `openpyxl`, lazy-imported); `kind` `carta` (credit-card report) exists only for BPER. It only normalizes — each movement is `{date, direction, account, movement, amount>0, description, details, tag, provisional, source_kind}` with `movement` using the Movimenti register's values and `tag` a hint (`stipendio`, `mutuo`, `possibile_giroconto`, `spese_bancarie`, `imposte`, `investimento`). Only movements from `IMPORT_START_DATE` (2026-01-01) are returned; Revolut currency exchanges (`cambio_valuta`) and BPER account card settlements (`regolamento_carta`) are not expenses and go to `ignored` instead (the settlement lines of the card report are dropped, otherwise card spending is counted twice). BPER files are cross-checked against their own row count and Totale row. No bank file carries a stable transaction ID, so matching relies on account+direction+amount+date.
  The page side (`// ===== Importazione estratti conto` in `financial-dashboard.html`) does the rest, nothing is written until the review screen is confirmed: the file is the source of truth for its window — a registered movement with the same account/direction/amount and date ±3 days is **replaced** (keeps its `id`, its manual category unless it is `Varie`/`Altro`/`Altro reddito`, and `autoMortgage`, otherwise `applyRecurringMortgage()` would regenerate the instalment), unmatched file rows are added, registered movements missing from the file are **flagged** (default "Mantieni", never auto-deleted). Imported entries carry `imported`, `source`, `noBalance: true` (account balances never change on import, so `deleteExpense`/`deleteTransfer` skip the balance reversal for them) and, for card purchases, `ccApplied: true`. Own-account transfers are paired across accounts (equal amount, opposite direction, ±3 days, at least one leg a `possibile_giroconto`/`transferHint`) and become an entry in `skender_fin_transfers_v1` replacing both legs; a leg already covered by a registered transfer is not imported. Categories: deterministic by tag → learned rules (`skender_fin_category_rules_v1`, learned only from categories the user set or already had, never from unreviewed AI output) → AI via `askAdvisor` (batches of 40, descriptions masked by `maskForAi`: IBANs, long numbers and names after "a favore di"/"Beneficiario" removed; no dates or account names are sent). `Varie` is never suggested because it requires a `necessity`.
- `avvia-dashboard.command` — double-clickable macOS launcher; runs `server.py` with `.venv/bin/python` when `.venv` exists.

## Running

```bash
python3 -m venv .venv && .venv/bin/python -m pip install anthropic   # once; for the AI chat install the chosen vendor's SDK (anthropic | openai | google-genai); for statement import also `xlrd openpyxl` — Homebrew Python blocks global pip
.venv/bin/python server.py   # serves the dashboard, opens browser, writes ./dati.json (avvia-dashboard.command does this)
```

## Architecture (single-file vanilla JS + Chart.js from CDN)

- **All state lives in `dati.json`, under keys prefixed `skender_fin`** (e.g. `skender_fin_v5` main data, `_investments_v1`, `_properties_v1`, `_expenses_v1`, `_transfers_v1`, `_category_rules_v1`, `_flows_v1`, `_chat_v1`, `_memory_v1`, `_theme`, `_last_modified_v1`). Each domain has `load*/save*` helpers and a `migrateLegacy*` function that lifts older fields out of the main `skender_fin_v5` object. Bump/migrate rather than silently changing the shape of stored data.
- **`dati.json` is the single source of truth — never use `localStorage`/`sessionStorage`/IndexedDB for data (not even UI prefs).** The page reads/writes only through `store` (top of the main `<script>`): `store.load()` does a *synchronous* GET at startup (if it fails the page shows "Dashboard non disponibile" and stops — no offline fallback), and every `store.setItem()` synchronously POSTs the **whole** state, so when it returns the data is on disk. Optimistic concurrency: GET returns an `ETag` (hash of the file), each POST sends it as `If-Match`; the server answers 409 if the file changed meanwhile (another tab) and 428 if `If-Match` is missing (a tab running an old version) — on 409 the page stops writing and asks for a reload; on network failure it alerts once and retries every 5 s, and `beforeunload` warns while something is unsaved. `migrateLegacyBrowserStorage()` is a one-time cleanup of the copy older versions kept in `localStorage` (imported into `dati.json` only if newer and the user confirms).
- `touchLastModified()` sets `LAST_MODIFIED_KEY`; call it from every data-mutating operation. That timestamp is distinct from `d.lastUpdated` (only set by the "Aggiorna dati" modal). CSV backup import compares against it: a backup not newer than current data can still be imported, but only after two explicit `confirm()` dialogs (summary with warning + definitive confirmation).
- **Startup automation** (bottom of the script): `migratePendingCcDueMonths()`, `applyMaturedCreditCardCharges()` (deferred credit-card charges hit the account balance on the due date) and `applyRecurringMortgage()` run on every load, then all `render*()` functions.
- **Net worth math** is in `render(d)`: liquid net worth deliberately excludes pension/TFR (Fondo Cometa) and properties.
- **Export/import**: CSV report and a versioned CSV backup (`BACKUP_FORMAT_MARKER`/`BACKUP_FORMAT_VERSION`), plus a recovery path for movements (`processRecoveredMovements`).
- **AI advisor chat**: two-pass flow in `sendChat()` — first prompt asks the model for a JSON calculation plan (`buildCalcPlanPrompt` → `parseCalcPlan`), expressions are evaluated locally by a small recursive-descent parser (`safeEval`, no `eval`), then a final prompt (`buildFinalPrompt`) includes the verified results plus `formatFinancialSnapshot(d)`. This exists to avoid LLM arithmetic errors — don't let the model compute numbers directly. A user-editable "memory" block is also fed into prompts. Market/tax context is a hardcoded snapshot, not a live feed.
- Theming uses CSS variables on `:root` with a `[data-theme="dark"]` override; charts are updated via `updateChartDefaultsForTheme()`.
